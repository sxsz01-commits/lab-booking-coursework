# 高校教学实验室预约管理行业分析

## 场景与依据

本方案以高校普通教学实验室为假设场景。学生或教师申请时段，实验室管理员维护房间与使用记录。教育部《高等学校实验室安全规范》要求高校落实安全责任、教育培训与安全准入；因此正式系统需要身份、培训和准入数据，而本课程 MVP 只验证预约闭环，不能替代安全管理系统。[1]

上海工程技术大学大型仪器开放共享平台公开展示预约及审核状态，说明高校已存在“资源可见—提交预约—审核”的数字化实践。[2] 不同学校的审批层级、开放规则和收费方式可能不同，不能照搬为本项目的真实需求。

## 目标用户与问题

| 角色 | 要完成的事 | 目前常见的阻碍（项目假设） |
|---|---|---|
| 使用者 | 找到实验室、挑选时段、提交和取消预约 | 多个表格或聊天记录难以确认实时空档 |
| 管理员 | 管理房间、审核申请、追踪使用情况 | 重复录入、冲突排查费时、记录分散 |
| 学校管理部门 | 看资源利用率与安全准入情况 | 数据口径不一、汇总滞后 |

上述阻碍是方案假设，需要访谈、预约台账与真实流程验证。

## 可比较的解决路径

1. 继续用共享表格：成本低，但并发冲突、权限和留痕较弱。
2. 使用通用日历：适合房间预约，但安全准入、设备关联与校内审批需额外配置。
3. 建立校内预约模块：可与统一身份认证、实验室台账和培训记录相连，但集成和维护成本更高。

课程 MVP 采用第 3 种路径的最小范围，先验证实验室目录、时段冲突和取消流程。

## 验收指标与后续验证

| 指标 | MVP 验收口径 | 正式试点需补充 |
|---|---|---|
| 冲突预约 | 相同实验室、重叠时段被拒绝 | 并发压力测试与管理员覆盖规则 |
| 操作闭环 | 新建后可查询、取消后释放时段 | 审批、通知、签到、爽约处理 |
| 数据质量 | 时间、人数、用途有基础校验 | 学号、角色、培训和安全准入校验 |
| 可追溯性 | SQLite 保存当前预约 | 操作日志、备份、权限审计 |
